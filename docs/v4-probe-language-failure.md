# V4失敗記録: 六択を一行で教えたら三問落とした

実験日: 2026-08-19

## 何が起きたか

V4の最初のlive startup probeでは、`0`〜`5`の対応を短い条件鎖としてLlama 3.1 8Bへ
説明した。返答は全部きれいな一文字だったが、意味は6問中3問しか合わなかった。

| probe | 期待 | 実際 | 結果 |
|---|---:|---:|---|
| ammoなしのWAIT | `0` | `4` | 誤り |
| 少し左のLEFT_SHORT | `1` | `2` | 誤り |
| 大きく左のLEFT_LONG | `2` | `2` | 正解 |
| 少し右のRIGHT_SHORT | `3` | `3` | 正解 |
| 敵なしのRIGHT_LONG探索 | `4` | `4` | 正解 |
| 中央のFIRE | `5` | `3` | 誤り |

- artifact: `runs/20260819-015308-09c01c25`
- OpenRouter報告実費: `$0.00004811`
- 結果: fail closed。ViZDoomへ操作権を渡さず終了

文法parserは成功していた。問題は「一文字が返らない」ではなく、8B modelが圧縮した
条件表をこちらの意図どおり読めなかったことだった。

## 直し方

local側へif文を足して補正するのは簡単だが、それでは「LLMが操作する」V4ではなくなる。
そこでmotor pathは一切変えず、promptへ6つの入出力例を並べ、その後ろに一般ruleを残した。

```text
v=0 x=9999 a=10 =>4
v=1 x=0    a=0  =>0
v=1 x=-150 a=10 =>1
v=1 x=-350 a=10 =>2
v=1 x=150  a=10 =>3
v=1 x=350  a=10 =>4
v=1 x=0    a=10 =>5
```

修正後のstartup probeは6 / 6で通過した。

- artifact: `runs/20260819-015346-729491dc`
- suite最大latency: 266 ms
- OpenRouter報告実費: `$0.00005981`

その後のseed 7〜16の10 runでも、起動時suiteはすべて初回6 / 6だった。

## 何が面白いか

回答を一文字へ削れば通信は速くなるが、**一文字を正しく出すための教科書が長くなった**。
最終promptは約196 prompt tokenで、completionは見た目一文字である。V4は帯域の節約には
なったが、意味の圧縮にはまだ成功していない。

そしてstartup probeがなければ、FIREのつもりでRIGHT_SHORTを出す身体を「動いた」と
呼んでいた。この時点では6択の全身テストを、Cloud LLMへ運転免許を渡す試験だと考えた。

## 2026-08-24 訂正: その運転免許試験にはカンニング穴があった

Colab T4二台で連続座標を追加検査したところ、従来の固定6問は6 / 6でも、敵なし・弾なしと
`x=-500..500`の20刻みを合わせた53問では**両laneとも29 / 53**だった。二台の回答は
53 / 53で一致したため、GPUやnetworkの偶然ではない。

固定probeの4問はsystem promptの例と同値で、残る左右SHORTも毎回`-150 / 150`という
canonical pointである。近傍を1だけずらすと、`-350`は正しいLEFT_LONGなのに`-351`は
RIGHT_LONG、`150`はRIGHT_SHORTなのに`149`と`151`はFIREへ変わった。

つまり6 / 6が証明していたのは、連続する数値区間の理解ではなく、**六つの見慣れた点に答えられる
こと**だった。数値比較そのものではなく例題・probe点へanchorしている挙動と整合するが、内部機序は
見えないので「暗記」とは断定しない。

この穴は実戦にも出た。二T4・100 ms観測では1,061判断中610回がFIREで、そのうち460回は
oracle rule上まだ旋回すべき位置だった。GPUを増やして判断帯域を倍にしてもkillが3.9から4.4へ
しか伸びなかった一因として、**速くなったぶん誤射判断も増幅した**可能性がある。

完全な測定値とraw artifactは
[二物理T4実験](experiment-three-t4-distributed-lanes.md#さらに見つかった本命-6--6-probeは境界理解を保証していなかった)へ保存した。

次は次の順で試す。

1. startupの固定6問は配線smoke testへ格下げする
2. prompt例と重ならないholdout点と境界両側を別suiteで測る
3. prefix KV cacheを保ったまま、未見点へ一般化する教え方を探索する
4. 失敗したらlocal補正で答えを直さず、policy失敗として記録する
